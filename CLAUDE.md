# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is a **monorepo of examples** for [Power Apps code apps](https://learn.microsoft.com/en-us/power-apps/developer/code-apps/) — custom web apps (React + TypeScript + Vite) that run natively inside Power Apps and talk to Power Platform connectors and data sources. It is not a single application; it is a collection of independent, self-contained app projects plus shared docs and tests.

- `templates/` — Scaffolding starting points (`starter`, `vite`). Each is a standalone npm project.
- `samples/` — End-to-end example apps (`HelloWorld`, `FluentSample`, `StaticAssetTracker`, `Dataverse`, `tanstack-app`). Each is a standalone npm project.
- `powercat/release-planner/` — Shipped sample apps (Release Planner + Lite), each a standalone npm project.
- `tests/` — Playwright e2e tests that build and run the `starter` and `vite` templates.
- `docs/assets/` — Shared reference files (`PowerProvider.tsx`, `AGENTS.md`) used in documentation.
- `sessions/` — Conference/workshop materials.
- `.claude-plugin/` — Marketplace/plugin metadata only. The actual AI-assistant plugin has **moved** to [microsoft/power-platform-skills](https://github.com/microsoft/power-platform-skills).

**Each app has its own `package.json`.** There is no root-level package manager. Always `cd` into the specific app directory before running npm commands.

## Common commands

Every app project uses the same Vite-based scripts (run from inside that app's directory):

```sh
npm install        # install dependencies
npm run dev        # start the local dev server (Vite) — use the "Local Play" URL it prints
npm run build      # type-check then build:  tsc -b && vite build
npm run lint       # eslint .
npm run preview    # serve the production build locally
```

### Tests (Playwright, from `tests/`)

```sh
cd tests && npm install
npx playwright install     # first run only — install browsers
npm test                   # runs both starter + vite specs

# Run a single template's spec:
TEMPLATE=starter npm test
TEMPLATE=vite    npm test

# Run a single test by name:
npx playwright test -g "should have working counter button"
```

The Playwright config (`tests/playwright.config.ts`) starts its own web servers: it `npm run build && npm run preview`s `templates/starter` on port 4174 and `templates/vite` on 4173. There is no test runner inside the individual app projects.

## Power Platform integration (the part that requires reading multiple files)

What makes these "code apps" rather than plain Vite apps is the Power Platform SDK wiring. Three pieces work together:

1. **`@microsoft/power-apps-vite` plugin** — added in every `vite.config.ts` (`powerApps()` in the `plugins` array). It handles the CORS/proxy setup that lets the local dev server authenticate against Power Platform.
2. **SDK initialization** — the app must call `initialize()` from `@microsoft/power-apps/app` on startup before any data access works. The canonical pattern is a `PowerProvider` component (see `docs/assets/PowerProvider.tsx`) that calls `initialize()` in a `useEffect` and wraps the app. Samples wire this into `main.tsx`/`App.tsx`.
3. **PAC CLI** (`pac`) — the Power Platform CLI manages app registration, data sources, and deployment outside of npm.

### PAC CLI workflow

```sh
pac code init --displayName "My App" --environment <environmentId>   # creates power.config.json
pac code add-data-source -a <apiId> -c <connectionId>                # generates typed models + services
npm run build && pac code push                                       # ALWAYS build before push
```

- `pac code init` creates `power.config.json` (environment ID + app config). This file is gitignored in app templates.
- `pac code add-data-source` generates code into `src/generated/` (and schemas into `.power/schemas/`). For lookups/tables, pass `-t <tableName>` and `-d <datasetName>`.
- **Deploying requires `npm run build` first, then `pac code push`** — pushing without a fresh build deploys stale output.

### Generated code is off-limits

Everything under `src/generated/` (models + services) and `.power/schemas/` is **auto-generated by the PAC CLI — never edit it by hand.** Regenerate via `pac code add-data-source` if a schema changes. Services expose `create()`, `get()`, `getAll()`, `update()`, `delete()`.

### Data-access conventions (see `samples/Dataverse/ARCHITECTURE.md` + `DEVELOPMENT.md`)

The Dataverse sample is the reference for production data patterns. Follow its three-layer architecture:

- **Components** (`src/components/`) — pure/presentational. Props down, events up. No service calls, no business logic.
- **Hooks** (`src/hooks/`) — own all state, async orchestration, and error handling. The *only* layer that calls generated services.
- **Generated services** (`src/generated/`) — the only way to reach the data layer. **Never use raw `fetch` or `axios`.**

Key query/data rules:
- Always pass `select`, `top`, and `orderBy` to `getAll()` to limit transfer.
- Write lookups with `@odata.bind` syntax: `payload['parentcustomerid_account@odata.bind'] = '/accounts(<guid>)'` (or `null` to clear).
- Read lookups from `_<field>_value` GUID columns; resolve to display names on-demand with individual `Service.get(guid)` calls rather than loading whole related tables (see `samples/Dataverse/LOOKUPS.md`).
- Wrap every operation in try-catch in the hook, expose the error via state, render it in a component.

## Conventions

- **Stack:** React 19, TypeScript ~5.9, Vite 7, ESLint 9 (flat config in `eslint.config.js`). The `starter` template adds Tailwind CSS v4, shadcn/ui (Radix primitives in `src/components/ui/`), TanStack Query + Table, React Router 7, Zustand, and Sonner.
- **Path alias:** `@/` → `src/` (configured in both `vite.config.ts` and `tsconfig`). Prefer it for intra-app imports.
- **App version display:** When building/deploying full apps, surface the app version in the UI and increment it on each `pac code push` (per `docs/assets/AGENTS.md`) — unless the user opts out.
- **Per-app AI instructions:** Some samples carry their own assistant rules (`samples/Dataverse/.github/copilot-instructions.md`, `samples/FluentSample/.github/copilot-instructions.md`, `.cursor/rules/`). Read these when working inside that specific sample.

## Scaffolding a new app

```sh
npx degit microsoft/PowerAppsCodeApps/templates/starter#main my-app
cd my-app && npm install
pac code init --environment <environmentId> --displayName "<name>"
npm run dev
```

Use `starter` for most apps; use `vite` for a minimal/custom stack.
